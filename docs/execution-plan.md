## 3 采集与保存契约

- 记录单位为一次成功且完整的实际上游尝试。先失败两次、第三次成功时，仅第三次进入正式档案；
  客户端请求 ID、上游尝试 ID 和实例 ID 分开，以便追踪及避免文件重名。
- Request 保存网关和传输插件完成改写后的实际发出正文，Response 保存供应商响应在网关
  业务转换前的正文。JSON/SSE 正文以原文字符串存放，JSON 必需的转义在读回后恢复原文；
  不解析后重新序列化原始业务对象，不删字段，不把 SSE 合成自定义答案对象。
- 外层信封草案包含 `schema_version`、记录/请求/尝试/实例标识、时间、厂商、账号非凭据标识、
  实际模型、协议、可取得的会话关联、`request`、`response` 及正文长度/摘要。
  具体字段名在阶段 2 固定；原文里的关联、模型和用量字段仍保留，外层信息不覆盖正文。
- WS 按实际上游业务轮次收集发出及收到的有序消息，不能按整条长连接只存一个文件；
  只保存线上实际传输的上下文，不伪造上游已有的隐藏历史。阶段 2 决定消息原文的容器。
- 成功采用供应商/协议的成功语义及有效结束条件，HTTP 200 单独不足以判断。
  正常工具调用轮次保留；正常的输出长度结束与网络断流区分，答案拒答或质量低不作为网络失败。
  无结束证据、显式错误和采集缺片段均排除，排除原因仅进入独立计数。
- 图片/视频/异步链路仍在覆盖目标内；任务提交成功不冒充生成成功，应关联提交、必要查询与最终结果。
  保存 URL 只证明保存了响应中的 URL，不表示图片/视频素材已归档；阶段 1、2 核实格式后，
  如保存原始二进制或另行下载素材需要改变单 JSON 约定或引入新调用，应先说明具体取舍再确定。
- 正文保真范围为应用层内容，解压前后的位置须在协议中写明；网络报文、TLS 密文及 HTTP 分块边界
  不与应用层原文混称。若实际需求涉及逐字节网络归档，应单独界定。
- 认证头、Cookie 和代理密码不属于采集必需的正文，外层来源信息不附带这些凭据。
  正文按已确认要求保留，可能含对话中的敏感内容；数据目录限制访问，真实档案不进入 Git 或插件包。
  现有安全文档禁止普通日志输出正文；新能力需显式界定受控数据档案与运行日志，运行日志仍保持原约束。

## 4 业务优先的资源与故障边界

- 主调用路径只做有界的片段复制和尝试入队，不等待磁盘、插件 RPC 或采集确认。
  内存复制仍有开销，以压测记录实际影响，不承诺零开销。
- 队列、并发采集数、单条暂存量和总暂存量均设额度；超额、插件不可用或任一片段丢失时，
  放弃整条采集，禁止把截断正文提交为完整档案。大请求采用分片，避免整条响应驻留内存。
- 插件后台流式写临时文件，收到成功且无缺片段的结束事件后，校验长度/摘要并在同一文件系统
  完成原子提交。业务失败或采集中断仅清理临时文件，正式目录只出现完整成功 JSON。
  缺失结束事件的临时文件在恢复/超时清理时处理，避免永久占用磁盘；正常写入崩溃窗口在测试中记录。
- 文件按日期和实例分目录，使用不可重用的调用标识命名；存储位于插件版本目录之外，
  插件升级、停用和卸载不连带删除已存档案。核实实际部署挂载后才能承诺跨容器重建保留。
- 达到磁盘额度或可用空间门槛时停止接收采集并告警；默认保留已有正式档案。
  自动删除、保留天数、外部归档和多实例集中存储作为独立配置取舍，不默认删除长期数据。
- 按阶段记录采集候选、业务失败排除、采集漏存及成功保存数量，重启/崩溃窗口和计数持久性
  明确说明；不宣称业务优先模式下零丢失或每次进程崩溃都能精确归因。
- 采集健康状态和运行时与传输插件区分；采集异常不拉低本体就绪状态，不占用 Cookie Pin 的互斥
  出站绑定，也不为采集改成另一传输方式。停用或交接期间允许漏存且可观测，原有请求继续完成。

## 5 验收与回退

第一版本地保存与下载方案：

- 正式档案保存在网关服务器本地持久化目录；页面下载后才进入管理员电脑。第一版不依赖云存储。
- 插件页面展示分页档案列表、保存时间及基础来源信息，支持单条 JSON 下载和按时间范围打包 ZIP。
  ZIP 中每次成功调用仍是一个原始 JSON，不转成 JSONL、训练格式或合并正文。
- 下载范围方案：必选时间区间，可叠加厂商、实际模型和上游账号筛选，条件取交集；
  时间按正式档案的调用完成时间计算，页面明确时区，采用起点包含、终点不包含的边界。
  “下载筛选结果”覆盖筛选命中的全部分页，“下载选中记录”仅覆盖明确勾选的记录，页面区分二者。
  创建导出前展示匹配文件数和原始总大小，确认后固定清单；新增数据不自动混入已经创建的导出。
  筛选维度及默认时间区间为待确认的页面方案，具体数量/体积额度依据资源验证确定，不写成已确认数值。
- 单次文件数、原始总字节、并发导出数和临时空间分别设上限，压缩后大小只作估算。
  超限时提示缩小范围或分批导出，禁止悄悄只取前若干条；清单必须保留源记录标识以便去重。
  管理员权限与筛选范围分别校验，筛选命中不等于获得读取权限。
- 现有 UI Bridge 主要用于配置和测试，需要新增受限的档案查询/导出能力；由宿主管理员鉴权后提供
  下载，iframe 不接收管理员令牌，不把数据目录暴露为公开静态目录。
  使用档案或导出标识定位数据，服务器校验其所属插件与数据目录，拒绝任意路径和符号链接越界。
- 仅导出已正式提交的完整成功档案。时间范围查询固定本次导出的文件清单，正在写入的临时文件排除；
  导出期间文件丢失或读取失败须明确报失败，避免静默交付缺项包。记录筛选时区和范围边界。
- 打包在后台执行，限制并发、总字节和临时空间；超额度时提示缩小时间范围。
  下载取消、打包失败或插件退出只影响导出，清理临时 ZIP，保留原始 JSON；下载本身不触发删除。
  资源限制与采集共用业务优先原则，验证打包和下载对模型调用的影响。
- 多实例或新旧槽交接时，标明档案所属实例，实际部署需确保下载端能读到原持久化目录；
  第一版不假设节点本地目录自动汇总。跨节点统一下载若需要额外存储或转发能力，单列方案。

| 验收面 | 必测场景 | 通过依据 |
| --- | --- | --- |
| 正文保真 | 未知字段、已有 rawdata、大整数、空白/转义、Unicode、工具定义/参数、多模态内联数据；SSE 事件换行；WS 多轮 | 从正式 JSON 读回的原文与模拟上游实际收到/发出的内容逐字节对比，摘要及长度一致；不只比较解析后的对象 |
| 成功筛选 | 普通成功、完整流、工具轮次、HTTP 错误、200 流内错误、断流、取消、重试后成功、探针及账号测试 | 应保存的次数与最终文件数一致；失败和不完整样本不进入正式目录，失败重试不污染成功 Request |
| 完整覆盖 | 阶段 1 全矩阵，含现有插件与 SDK 分支、压缩响应、原生 WS、图片/视频和异步任务 | 每条链路有证据；异步最终状态与提交关联，素材保存边界标明；缺项保持未完成 |
| 故障隔离 | 磁盘满、权限错误、慢磁盘、队列满、插件卡死/退出、IPC 中断、启动失败、重启残留及重复结束事件 | 业务响应、计费和 readiness 与关闭采集时一致；无无限等待/队列增长，无残缺正式文件；计数和告警符合可观测边界 |
| 性能与资源 | 同一负载下关闭采集、正常采集、采集故障；覆盖大上下文与长流 | 先记录基线，再冻结延迟、首字、吞吐、CPU、内存及磁盘预算；超预算先修复或调整额度，不能凭直觉宣布无影响 |
| 生命周期兼容 | 旧 Cookie Pin、旧插件包、签名/版本约束、单活交接、旧实例收尾、采集启停/升级 | 原有传输和生产切换约束保留，采集故障不扩大成全站故障；升级后数据可读 |
| 本地下载 | 管理员与未授权访问、单条 JSON、时间范围边界、ZIP 解压、路径越界、临时文件排除、文件消失、下载取消、空间不足、并发打包及实例交接 | 未授权和越界读取被拒绝；下载字节与原档案一致，ZIP 清单与筛选一致；失败不返回伪完整包、不删除源数据、不阻断模型调用 |
