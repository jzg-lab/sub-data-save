# sub-data-save

为 Sub2API 采集成功调用的上游原始 Request / Response，积累用于知识库和后训练的数据档案。

**当前状态：需求与执行计划已整理，插件功能尚未实现，没有可安装包。**

## 第一版目标

- 覆盖网关支持的全部厂商与账号类型，每次成功且完整的上游调用保存一个 JSON。
- 保留请求、响应原文及全部原有字段，包括已有的 `rawdata`、工具调用和流式事件。
- 排除报错、断流及残缺数据，正常工具调用保留；成功不代表答案质量已审核。
- 保存到网关服务器本地持久化目录，管理员从后台插件页面下载到电脑。
- 支持单条 JSON 和筛选后 ZIP 下载；包内仍然每次调用一个 JSON。
- 业务优先：采集或导出故障不阻断模型调用，资源有上限，漏存单独统计告警。

## 文档入口

- [已确认需求](docs/requirements.md)：用户已确定的目标和行为边界。
- [执行计划](docs/execution-plan.md)：两个仓库的分工、实施顺序、数据契约、下载方案与验收。

下载筛选方案为时间范围加厂商、实际模型、上游账号；单次文件数、总大小、并发及临时空间设限。
筛选默认值和具体额度尚待确定；多模态二进制、外链素材和异步任务归档细节在链路核查后固定。

## 与网关的关系

[sub2api-r3-fix](https://github.com/jzg-lab/sub2api-r3-fix) 负责实际出站采集、完整性判定、
异步派发以及管理员下载入口。本仓库负责采集插件的接收、保存、查询、导出、页面及签名发布。

现有插件协议只支持 OpenAI OAuth 出站传输，覆盖全部厂商需要扩展宿主能力；
采集插件需与 Cookie Pin 共存，采集异常不影响传输插件和主服务就绪状态。
当前没有实现代码或性能验证，不能直接安装到现有网关实现上述功能。
